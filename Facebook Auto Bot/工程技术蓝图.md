## 1. 项目概述

**FAhubX** 是 Facebook 多账号自动化 SaaS 平台。每个租户管理多个 Facebook 账号，通过 Puppeteer 自动化执行养号 / 加好友 / 自动聊天 / 加群 / 发图文 / 自动 follow / 留言 / 组合任务。

### 双部署模式

| 模式 | 适用场景 | 部署位置 |
|---|---|---|
| **Cloud** | 多租户 SaaS，管理员控制 | VPS（共享） |
| **Local** | 客户在自己电脑上跑，License Key 激活 | C:\FAhubX（每客户一份） |

通过 `DEPLOY_MODE=cloud` / `DEPLOY_MODE=local` 环境变量区分。

### 当前版本：**v1.4.2**

含 3 个 hotfix：
1. Enterprise plan 在 admin 页正确渲染
2. 「查看窗口」cookie 失效自动密码登录
3. Warmup fire-and-forget（同组多账号能并发 fire）

## 9. 关键算法 / 业务逻辑

### A. 暖化时间矩阵（v1.4.0+ 自适应）

文件：`backend/src/modules/warmup/warmup-windows.util.ts`

```
groupCount ≤ 6: 组间错峰 60 分钟（整点）
  G1=[08:00, 14:00, 20:00]
  G2=[09:00, 15:00, 21:00]
  ...
  G6=[13:00, 19:00, 01:00]

groupCount > 6（Enterprise，最多 9 组）: 组间错峰 floor(360/N) 分钟
  N=9 → 40 分钟
  G1=[08:00, 14:00, 20:00]
  G2=[08:40, 14:40, 20:40]
  ...
  G9=[13:20, 19:20, 01:20]
```

每个窗口持续 **30 分钟**。窗口外 30 分钟检测到没触发 → `missedToday++`。

### B. 组内 5 分钟错峰

```
ACCOUNT_STAGGER_MIN = 5
trigger_offset = position_in_group * 5
窗口起始 + trigger_offset 是该账号的 5 分钟槽
position * 5 ≥ 30 → 跳过（超出窗口，建议组内 ≤ 6 账号）
```

### C. 4 个养号包

| Mode | 行为 | 转 P3 时机 |
|---|---|---|
| `P1` 单独孵化 | Day 1-7 用 P1 动作 | day > 7 |
| `P2` 单独激活 | Day 1-7 用 P2 动作 | day > 7 |
| `P1+P2` 完整 | Day 1-7 P1 / Day 8-14 P2 | day > 14 |
| `P3` 维护 | 永远 isMaintenance | 不转 |

转 P3 时：`packageMode='P3'` + `startedAt=now`（重新算 Day 1）+ `lastFiredWindow=null`

### D. 配对算法（auto_chat）

`warmup.service.ts` `findChatPartner`：
1. 同组 + 未删除 + active warmup + 不是自己 = 候选池
2. 优先选 VPN 不同的（防风控）
3. 没有 → 退而求次选同 VPN（task name 加 `[IP⚠️]`）
4. 候选池为空 → 调用方降级为 `simulate_human_behavior`

### E. ensureLoggedIn 三步流程

`simple-tasks.controller.ts` line 404+ + `task-auto-runner.service.ts` line 483+：
1. **检查当前 URL** + logged-in indicator → 已登录返回 true
2. **注入 cookies**（DB `facebook_accounts.cookies` jsonb）→ reload 检查
3. **密码登录回退**：goto /login → fill email/pass → Enter → 检查 finalUrl
   - `checkpoint` / `two_step` → 失败（需手动处理）
   - 仍 `/login` → 失败（密码错）
   - 否则 → 成功 + 更新 `loginStatus=true`

> **v1.4.2 修复**：`show-browser` endpoint 也复用此流程（之前只注入 cookie，cookie 失效就停在 profile chooser）。

### F. Warmup fire-and-forget（v1.4.2 修复）

**Bug**：v1.4.0 5 分钟错峰 vs `simulate_human_behavior` 25 分钟时长不兼容。`scheduleTick` 用 `tickInFlight` 全局锁 + `await Promise.all(tickOne)`，导致 8:00 触发 #01 后整个 cron 被锁 25 分钟，#02/#03（5min slot 8:05/8:10）永远轮不到。

**修复**：`tickOne` 在 fire 条件满足时**先 save** `lastFiredWindow + firedTotal + lastCheckedAt`，然后**不 await** action（fire-and-forget）：
```ts
void this.executeWindowAction(p, account, info, activeIdx)
  .catch(err => this.logger.error(...));
return;
```
浏览器并发由 `BrowserSessionService` 的 per-account semaphore 自管。

### G. License 心跳

- 间隔：**30 分钟**
- 离线宽限：**24 小时**（断网超过 24 小时锁系统）
- 绑定：**1 台电脑**（machine fingerprint = node-machine-id），换机器需 Admin 解绑

## 14. 故障处理手册

### A. SSH 密码被拒（3 步排查）

按顺序：
1. **逐字符手敲**密码 `)A5z$T)5u?j#FqjL`（不复制粘贴 — Windows Terminal 粘贴 `$ ) #` 经常带隐藏字符）
2. **PowerShell 标准化**：
   ```powershell
   Set-Clipboard -Value ')A5z$T)5u?j#FqjL'
   ```
   然后在 SSH 提示处右键粘贴
3. **确认密码真改了** → Vultr 控制台 `Server → Reset Root Password`

> AI agent 不应该尝试自动 SSH（沙箱没 sshpass，也不该把密码塞进自动化）。

### B. Git push 被沙箱拦截

按 [§12 部署 Playbook](#12-部署-playbook) 描述处理。

### C. Backend 启动失败（启动后立刻 crash）

`start.bat` 用 `start /min` 启动，stderr 丢失看不到错误。诊断：
```bash
cd /c/FAhubX/backend
timeout 15 "/c/FAhubX/node/node.exe" dist/main.js 2>&1 | head -80
```
最常见原因：
- **DB 连接失败**：检查 `.env` 的 `DB_PASSWORD` vs PG 实际密码
- **端口冲突**：见 §14.D
- **JWT_SECRET 缺失**：生产环境校验默认密钥

### D. 端口冲突（最近一次：telehubx 占了 5433/6380）

**症状**：start.bat 报 `PostgreSQL already running`，但 backend 连 PG 报 `password authentication failed for user "postgres"`。

**真相**：`start.bat` 用 `pg_isready` 检查 5433 → 看到端口有响应就跳过启动 → 但实际上是别的项目的容器在监听 5433。

**诊断**：
```bash
# 1. 看 5433/6380/9600 谁在监听
netstat -ano | grep -E ":5433.*LISTENING"

# 2. 拿 PID 查进程
powershell -NoProfile -Command "Get-CimInstance Win32_Process -Filter \"ProcessId=<PID>\" | Format-List"

# 3. 看 docker container 端口映射
docker ps --format "table {{.Names}}\t{{.Ports}}"
```

**修复**：让占用方换端口（**禁止**自己动其他项目的容器，见 §15 协议）。

### E. obfuscator OOM（installer build 时）

**症状**：`installer/build.bat` 跑一半报 OOM。

**修复**：build 前**必须**清旧 dist：
```powershell
Remove-Item "backend\dist" -Recurse -Force
Remove-Item "installer\staging\backend" -Recurse -Force
```
否则上次混淆过的 .js 再被混淆 → 文件指数膨胀 → OOM。`build-backend.bat` 已自带清理但保险起见手动清。

### F. 大文件 Cloudflare 下载断流（v1.4.x installer ~463 MB）

如果客户反馈下载慢 / 断流，加 DNS-only 子域名 `downloads.starbright-solutions.com` 绕过 Cloudflare 代理（CF Free 大文件不友好）。当前还没遇到，预防方案。

### G. 用户说「养号没动作」

```bash
# 1. backend 跑了没
pm2 logs fahubx-backend --lines 100 | grep -i warmup
# 本地：tail -100 C:\FAhubX\logs\backend.log

# 2. DB 进度记录
psql -d fbautobot -c "SELECT * FROM warmup_progress;"

# 3. 检查窗口 + lastFiredWindow
psql -d fbautobot -c "SELECT \"accountId\", \"packageMode\", \"firedTotal\", \"missedToday\", \"lastFiredWindow\", \"lastCheckedAt\" FROM warmup_progress;"

# 4. 用户的 groupCount
psql -d fbautobot -c "SELECT email, preferences->'warmup' FROM users;"
```

### H. 用户说「前端某页白屏」

最常见两个原因：
1. **TransformInterceptor 解包问题**：service 漏 `unwrapApi(response.data)` → 接到的对象是 `{success, data, ...}`，render 时报错
2. **i18n key 缺失**：`t('xxx')` 返回 `undefined`

→ F12 看 console 报错。

## 15. 多项目共机协议

### 背景

本机同时跑 **WAhubX** + **FAhubX** + **telehubx** + **可能其他项目**，全都依赖 `node.exe` / `chrome.exe` / Docker 容器。**已发生过误杀其他项目的事故**。

### 绝对禁止

1. ❌ `taskkill /F /IM node.exe`
2. ❌ `taskkill /F /IM chrome.exe`
3. ❌ `Stop-Process -Name node`（不带过滤）
4. ❌ 任何全名匹配的批量进程杀
5. ❌ 自己动其他项目的 docker container（`docker stop <他人容器>`）

### 正确杀进程的方法

**第一选择**：用项目自带的 stop 脚本
```powershell
& "C:\FAhubX\stop.bat"   # 只杀 FAhubX 自己的进程
```

**精确按 PID**：
```powershell
taskkill //F //PID <pid>
```

**按端口找 PID 再杀**：
```powershell
Get-NetTCPConnection -LocalPort <port> -ErrorAction SilentlyContinue |
  Select-Object -ExpandProperty OwningProcess -Unique |
  ForEach-Object { Stop-Process -Id $_ -Force -ErrorAction SilentlyContinue }
```

**按命令行路径过滤**：
```powershell
Get-CimInstance Win32_Process -Filter "Name='node.exe'" |
  Where-Object { $_.CommandLine -like '*C:\\FAhubX\\*' } |
  ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
```

### 端口冲突时的协议

1. **新项目启动前**：`docker ps` + `netstat -ano` 看现有占用
2. **冲突时**：**自己换端口**，不动别人的容器
3. 给其他项目 agent 留消息（如 telehubx 案例：让 telehubx 让出 5433/6380/9600）

### chrome.exe 路径区分

| 路径 | 项目 |
|---|---|
| `C:\FAhubX\data\browsers\` | FAhubX Puppeteer |
| `AppData\Roaming\wahubx\` | WAhubX runtime |
| 其他 | 用户日常浏览 / 别项目 |
